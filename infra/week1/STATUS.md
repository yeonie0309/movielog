기준일: 2026-11-22 KST. 원본 Notion 수정과 UMC 제출은 하지 않았다.

## 완료 범위

0주차는 Google 가입·프로젝트 생성·무료 플랜 확인을 완료했다. 가입 직후 크레딧 $100·미납 $0 화면은 사용자가 제공한 원본으로 보관했다. CLI는 임시 로그인으로 연결했고 장기 Access Key를 만들지 않았다.

1주차는 기존 EC2/RDS 배포 기반이 없어서 ECR·RDS·SSM부터 구성했다. Sydney 기본 VPC, AL2023 ARM64 EC2, 현재 기본 지원 버전 MySQL 8.4.11을 사용했다. 새 DB에는 공개 스키마로 테이블 3개만 생성했으며 로컬 데이터를 업로드하지 않았다.

공통: GET /health, 10 RPS, 요청 제한 5초, baseline 15초, 연속 실패 3건 이상을 순단으로 판정했다. 최종 세 실행 모두 baseline 실패율 0, warnings 없음이다. 단일 배포 120초, 무중단 배포 240초다. 선택 미션은 최대 480초로 시작해 정상 복구 후 30초를 더 관측하고 약 313초에 의도적으로 종료해 원본 상태가 stopped다.

공식 도구의 측정·통계·순단 판정 엔진은 수정하지 않았다. 새로고침 시 실제 조건과 완료 결과를 복원하는 UI 보정만 patch로 남겼다. 실패한 사전 시도도 별도 보관했다. 0ms는 해당 요청 조건과 구간에서 관측된 결과다.

## 검증·보존·정리

- 백엔드 테스트 73개, 배포·정리 안전장치 테스트 6개, 타입 검사와 diff 검사 통과.
- /health는 DB SELECT 1과 2초 응답 제한을 확인하며 실패 시 내부 정보를 숨긴 503을 반환한다. 실험 전용 이미지만 의도적으로 500을 반환한다.
- 실제 컨테이너의 사용자 node, v0.1.2 이미지, HTTP 200, 두 서버 cloud-init 완료를 확인했다.
- RDS 비공개·암호화·Single-AZ, 앱 사용자 DML 권한만 허용. 초기화용 master 파라미터는 초기화 직후 삭제했다.
- ALB의 공개 HTTP 경로는 /health만 허용했다. 앱 포트는 ALB SG만, DB는 앱 SG만 허용했다. SSH를 열거나 외부 경로로 로그인·개인정보를 보내지 않았다.
- 생성된 실제 비밀값 3개가 공개 파일에 없고 .local이 Git에서 제외되는 것을 확인했다. 정리 후 로컬 상태에서도 생성 비밀값을 제거했다.
- 사용 한도로 중단된 동안 리소스는 유지됐다. 재개 후 임시 로그인 갱신·정상 상태 확인·자원 정리를 마쳤다. 유료 플랜 전환은 하지 않았다. 정확한 사용액은 청구 반영 후 별도 확인 대상이다.
- 기본 VPC·서브넷·AWS 서비스 연결 역할과 기존 로컬 DB를 유지했다.
- 브랜치 codex/infra-week-1은 feature/week-8-backend 기준이다. main에는 이전 전체 과제가 없어 변경 범위를 분리했다. 기존 미추적 파일 3개는 변경하지 않았다.
