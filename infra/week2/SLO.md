# MovieLog Infra2 SLO 정의서
상태: 설계 완료. 실제 클라우드 측정 및 알림 수신 전이며 아래 목표를 달성했다고 주장하지 않는다.

- 대상: 인증된 POST /movie-records (우리 프로젝트 실제 경로). 평점과 즐겨찾기 동시 저장.
- 사용자 관점: 유효한 영화 기록 저장 요청이 성공하고, 오래 기다리지 않아야 한다.
- 지연 SLI: 요청 duration histogram에서 계산한 전체 p95. 서버 시간은 seconds, 보고서는 ms로도 병기.
- 지연 SLO: 정상 운영 목표 부하에서 p95 ≤1초. 부하별 실측을 확인한 뒤 목표 RPS 범위를 확정.
- 성공 SLI: 생성한 유효 요청 중201 응답 비율. timeout·network·5xx·4xx·미전송(dropped)을 나눠 보고한다.
- 성공 SLO: 정상 운영 목표 부하 구간에서201 비율 ≥99%. 잘못된 토큰/중복409는 시나리오 오류로 별도 분석하되 성공으로 집계하지 않는다.
- 관측 창: 대시보드5분 rate, 부하 실험은 단계별40초+scrape여유. 두 수치를 혼동하지 않는다.
- 포화 판단: 목표 RPS 증가에 실제 성공처리량 증가가 멈추고, p95·timeout이 증가하는지 CPU·DB연결과 함께 확인.
- 알림: p95 >1초가1분 지속. 별도 AppDown으로 데이터 미수집을 감지. 오류율 추가알림은5xx비율 >0.01이1분 지속.
- 검증: 각200/400/600/800 RPS 단계마다 새 테스트 회원·새 JWT 사용, 고유 movieId. 사전201 probe는 counter와 겹치지 않는 값 사용.
- 제외: /health, /metrics, Swagger 경로는 앱 지연/요청수에서 제외. 라벨은 method/route/status만 사용.
- 외부 제공: 개인 계정·실제 데이터는 사용하지 않는다. 테스트 전용회원 생성 후 정리한다. 로그/Trace수집은 본문에서 범위 제외됨.
